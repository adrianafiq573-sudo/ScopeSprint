What “rules and templates” means

Instead of sending the idea to an AI model, ScopeSprint checks for a few known beginner web-app patterns and picks matching tasks written ahead of time. If it does not recognize the idea, it uses a general small-web-app plan. That keeps the first demo free and offline, while being honest that it cannot deeply understand every idea.

CORE TASKS

Keep the useful minimum

Core tasks come first so there is a small, usable version to build.

TIME FIT

Use one measuring unit

Hours from the form are converted to minutes for comparison. Short estimates show minutes; longer ones show hours.

OPTIONAL TASKS

Save the rest for later

Optional features are added only while they fit. Postponed features include a short reason.

TOO LITTLE TIME

Show an honest warning

If even the core plan is longer, ScopeSprint shows the smallest useful plan and its approximate minimum time.

Follow the main journey

Open each step to see which part of the app is responsible. These connect directly to headings in prd.md.

1. Enter and validate an idea Dashboard

The form checks trimmed project name and idea text plus a positive number of hours. Errors stay beside the field, entered information is preserved, and invalid input cannot create a project.

PRD: Dashboard and Project Creation · States and Boundaries

2. Turn the idea into an MVP Planner

Keyword rules choose a curated template or the general fallback. The plan uses ordered Plan, Build, and Test & Polish stages. For oversized ideas, the original description is displayed exactly as typed, then core MVP tasks and postponed ideas are explained.

PRD: Dashboard and Project Creation · Project Task Plan

3. Edit tasks and watch progress Project plan

Checking a task recalculates progress right away. A custom task needs a title and stage (Plan by default); description and positive time estimate are optional. It appears at the end of the selected stage, starts incomplete, and does not need completion criteria.

PRD: Project Task Plan

4. Return to saved work Browser storage

Real projects, progress, and the chosen theme are saved in the same browser for the same local website address. A user can permanently delete one project after confirming; other projects are kept. This is local-only storage: it does not sync to another device. If the browser blocks saving, the app should say so clearly.

PRD: Dashboard and Project Creation · Project Task Plan · Theme and Responsive Use

5. Explore the sample safely StudyBuddy

The demo has its own temporary state, including a working assignment form and screen wireframe. Reset or reopening it restores the original example. The sample is never stored in My Projects and cannot overwrite real work.

PRD: Interactive StudyBuddy Sample

Run and verify

There are no package downloads, paid services, accounts, or API keys. Python's small built-in server serves the files locally; Node runs the logic tests.

Start the app

From the project folder, run python -m http.server 8000 --bind 127.0.0.1, then open http://127.0.0.1:8000/.

Keep the terminal open and use the same address each visit for saved data.

Run checks

In another terminal, run node --test tests/planner.test.mjs tests/storage.test.mjs tests/sample.test.mjs tests/theme.test.mjs.

Then manually create, edit, delete with confirmation, refresh, and revisit a project; try invalid inputs, both themes, sample reset, assignment actions, and a narrow mobile window.

The three planned app slices are implemented; the automated checks cover planner, storage, sample reset, and theme choice. Manual browser checks are part of the build review.

Decisions and tradeoffs

Why no real AI model in the first demo?

Rules and templates are predictable, work offline, and avoid API setup or cost. The tradeoff is limited pattern recognition. The interface must not call this model-generated.

Where are real projects saved?

In the browser's localStorage, for this browser and website address. That avoids accounts and a backend, but there is no cross-device sync and clearing browser data can remove projects.

What is deliberately outside the first build?

Accounts, collaboration, payment, a complex server, production-scale plans, and broad project types. The first demo proves the main create-plan-track-save experience.
