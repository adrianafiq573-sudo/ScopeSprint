Plain English: ScopeSprint should help someone answer “What can I do next?” and show them that they’re moving forward.

Who it helps and what makes it different

For: students and first-time builders working on small, beginner-friendly web app projects.

Core idea: make an overwhelming idea feel achievable by splitting it into prioritized tasks with clear completion goals.

When an idea is too big: suggest a smaller MVP (the smallest useful first version) instead of pretending one beginner can build a production-scale app in the available time.

What the first version includes
Idea and time input Prioritized MVP tasks Clear completion goals Editable tasks Completion checkboxes Progress indicator Browser saving Useful sample project

Keep the app simple and responsive so the main flow is easy to follow on different screen sizes.

What stays out of the first version
Production-scale social network or Uber clone Complex backend system Payment processing

These would make the project much larger without helping prove the core idea. Broader project types can be reconsidered later.

What counts as “working”

In a short screen demo, a beginner enters a small web app idea and available time, sees a prioritized plan with clear completion goals, completes a few tasks, and sees progress update and stay saved after a page refresh. An oversized idea should produce a smaller MVP suggestion.

Important decisions still to make later

This scope describes what the app should help someone do. The technical plan will decide how plan generation works. We should not describe the app as using a real AI model unless one is actually connected. A backend or paid API should only be considered if the technical plan shows it is essential.
