Product requirements · beginner-friendly overview

ScopeSprint

Turn a small web app idea and available time into an achievable plan. Then make it your own and track progress.

Approved product requirements

The main journey

Three screens; one end-to-end path from idea to visible progress

Plain English: Users start with their own idea or try the isolated StudyBuddy demo. A real project opens as a staged checklist, and changes remain available when they return.

Dashboard and creating a project

The app opens directly to the dashboard—no welcome screen—with the headline “Turn your idea into a plan.”, a short explanation, the project form, sample entry point, and preview. Returning users also see the most recently opened project and a card list of saved projects.

Required form fields: project name, idea description, and time labeled “How many hours do you have?” with hours beside the input. Accept positive numbers and decimals such as 2.5; reject blank/whitespace-only, non-numeric, zero, and negative values. On submit, each invalid field gets its own inline error; entered values stay put. Correcting a field clears that field's message. Invalid input never creates a project, generates a plan, or navigates away.

When an idea is too large for its time: add a “How we narrowed your idea” explanation. Show the original description exactly as entered, the time-fitting MVP and its core features, and postponed features with reasons.

  • After valid submission, open the new project plan directly.
  • “Continue Where You Left Off” shows name, percent, completed/total count, and a Continue Project action.
  • “My Projects” cards show name, short description, progress/count, last updated time, and open action.

Check: invalid input keeps the user on the dashboard and preserves other fields; valid input opens a plan; a too-large idea shows the three-part narrowing section.

Project plan and task behavior

The plan starts with project name and description, a name-edit action, overall progress, completed/total task count, and a Back to Dashboard link. Tasks sit inside labeled, collapsible stages with per-stage counts. Stage order communicates priority.

  • Each generated task has an action-oriented title, one or two plain-English sentences, an observable completion goal, an approximate time estimate, and a complete/incomplete checkbox. Show short estimates in minutes and longer estimates in hours; make clear estimates are not guarantees and compare totals against available hours using one consistent unit.
  • Task details can expand or collapse.
  • First-demo editing: change the project name, rename a task, add a task, and check or uncheck a task.
  • A custom task requires a title and stage (Plan, Build, or Test & Polish; default Plan). Description and a positive numeric estimate are optional; the estimate can use minutes or hours. Completion criteria are not required. Append it to the selected stage, keep existing order, start incomplete, show it immediately, update counts/progress, and save it with that project.
  • Overall and stage counts update immediately; changes save automatically and remain separate per project.

Check: checking a task immediately changes its status, stage count, overall count, and progress bar; after refresh, the same project and its progress are still available. Estimates compare consistently with the hours budget regardless of whether their display uses minutes or hours.

StudyBuddy sample demo

StudyBuddy: A Student Planner App is a realistic beginner-sized example, clearly marked as a sample. It shows an overview, MVP goal, Planning/Building/Testing stages, estimates, completion goals, expandable task detail, checkboxes, and progress.

  • “Reset Demo” restores the sample baseline and never alters a user's own projects.
  • “Create My Own Project” goes to the project creation form.
  • “Back to Dashboard” returns to the dashboard.
  • The sample needs no account and works offline after the app has loaded.

Check: sample progress updates when a task is toggled; reset restores the original sample; sample tasks never appear in or change a user's projects.

Technical approach agreed for the first demo

Use a small set of keyword-matched prewritten task templates, with a general small-web-app fallback. This rules-based planner works offline after the app loads and must not be presented as a real AI model. Compare time in minutes internally. Show an honest warning when the minimum useful plan still exceeds the budget.
