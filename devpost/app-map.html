How ScopeSprint works

Think of app.js as the traffic guide: it receives a click, asks the right helper module to do the work, then redraws the screen. The diagram shows the path a project follows.

The main path

1 · InputDashboard formapp.js checks the name, idea, and hours.
2 · DecidePlan rulesplanner.js picks a template and fits tasks to time.
3 · ShowProject planapp.js draws stages, criteria, and progress.
4 · KeepBrowser storagestorage.js remembers real projects on this browser.

Screen and actions · js/app.js

renderDashboard() draws the form, sample preview, recent project, and saved project cards. Form submission calls buildPlan(), saves the result, and opens it.

renderPlan() draws the plan and connects the checkbox, edit-title, edit-name, and add-task controls. isSample decides whether changes may be saved.

Useful route: open app.js

Planning rules and math · js/planner.js

validateProjectInput() rejects blank names or ideas and non-positive hours. chooseTemplate() looks for a supported keyword pattern, then uses the general plan when none matches.

buildPlan() keeps estimates in minutes, includes core tasks first, and explains postponed features. calculateProgress() counts checked tasks instead of storing a separate percentage.

Useful route: open planner rules

Saved projects · js/storage.js

loadProjects() reads the saved list. saveProject() finds one project by ID and replaces only that entry; the recent-project pointer uses a separate storage key.

This is local to the current browser and website address, so it does not sync to another device.

Useful route: open storage helpers

Sample and theme · js/sample.js, js/theme.js, styles.css

createSampleProject() returns a fresh copy each time. The theme helper reads the device setting first, then remembers a manual choice. CSS variables recolor the whole interface.

Useful routes: sample data, theme behavior, color and layout rules

Checks · tests/

Planner tests check input and plan rules; storage tests use a small pretend browser store; sample tests confirm every demo starts fresh; theme tests check saved choice versus device preference.

Run them from the project folder with node --test tests/planner.test.mjs tests/storage.test.mjs tests/sample.test.mjs tests/theme.test.mjs.

A short code tour

  1. Start at index.html. The page has one empty #app space. JavaScript fills that space; the theme button stays in the page header.
  2. Follow the form in app.js. It validates the entries, then asks planner.js for a plan.
  3. Follow one checkbox. The task's completed value changes. Progress is calculated from all task values, then the view is redrawn.
  4. Check which kind of plan is open. A real project calls rememberProject(); the StudyBuddy demo skips it, so Reset Demo can make a clean copy.
  5. Follow the theme button. theme.js changes one page attribute; styles.css swaps semantic color variables to update every surface.

Practice you can reuse in your next project

Try a small data change and let a test tell you whether the behavior still matches your intention.

  1. In js/sample.js, add one beginner-sized task to the Test & Polish stage. Give it a unique ID, title, description, completion goal, estimate, priority, and completed: false.
  2. In tests/sample.test.mjs, update the expected task count from 6 to 7.
  3. Run the test command above. See how the progress calculation includes the new task without editing the screen or storage code.

If you try this, keep the edit if the test passes and you can see the added task in the demo; otherwise undo the change and inspect the test output first.

ScopeSprint uses transparent rules and templates. It does not call a real AI model. Start with a small change, check the result, then move on.
